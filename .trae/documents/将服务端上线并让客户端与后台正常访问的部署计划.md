## 部署目标
- 将 `server` 服务以可维护、可监控的方式上线，提供稳定 HTTPS 访问。
- 客户端以 `BASE_URL` 远端接口工作，后台页面（登录/书籍列表/新建/页面管理/上传）可正常访问。
- 完整联调：主页编辑推荐与推荐流分页、阅读页相关推荐、后台创建内容并在客户端展示。

## 方案选择
- 托管平台（推荐 Render/Fly/Railway）：快速、免运维，开箱 HTTPS 与健康检查。
- 自建服务器（Docker + Nginx）：适合自控环境与定制需求。

## Render 托管部署步骤
1) 仓库与构建
- 使用现有容器化文件：`server/Dockerfile` 与 `server/deploy/render.yaml`。
- 在 Render 创建 Web Service，Docker 环境，上传或连接代码仓库。
2) 环境变量
- `CORS_ALLOWED_ORIGINS`：设置为 `*` 或限定域（如后台域与调试工具）。
- `JWT_SECRET`：生成随机值。
- `DATABASE_URL`：后续接入数据库时设置；当前内存数据可为空。
3) 健康检查
- 配置 `healthCheckPath: /healthz`，服务启动后应返回 `ok`。
4) 静态资源
- 容器内 `uploads/` 用于开发阶段图片存储，Render 会提供持久卷或建议改为对象存储（生产）。
5) 验证
- 访问 Render 分配的 HTTPS 域名：`https://<service>.onrender.com/healthz`。
- 后台登录页：`https://<service>.onrender.com/admin/login`，登录后访问 `admin/books` 等页面。
- 公共接口：`/v1/editor-picks`, `/v1/books`, `/v1/books/{id}`, `/v1/books/{id}/recommendations`。

## 自建服务器（Docker + Nginx）部署步骤
1) 准备环境
- 安装 Docker 与 docker-compose；准备域名与证书（Let’s Encrypt/Cloudflare）。
2) 构建与运行
- 在 `server` 目录执行：
  - 构建：`docker build -t picturebook-server .`
  - 运行：`docker run -d -p 8080:8080 -e CORS_ALLOWED_ORIGINS="*" -e JWT_SECRET="<random>" --name picturebook picturebook-server`
- 添加持久卷：`-v /var/picturebook/uploads:/app/uploads`（开发上传使用）。
3) 反向代理（Nginx）
- 将 `https://api.yourdomain.com` 代理至 `http://localhost:8080`，开启 HTTPS 与 gzip；示例：
```
server {
  listen 443 ssl;
  server_name api.yourdomain.com;
  ssl_certificate /etc/letsencrypt/live/api.yourdomain.com/fullchain.pem;
  ssl_certificate_key /etc/letsencrypt/live/api.yourdomain.com/privkey.pem;
  location / {
    proxy_pass http://127.0.0.1:8080;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
  }
}
```
4) 验证
- 访问 `https://api.yourdomain.com/healthz` 返回 `ok`。
- 访问后台 `https://api.yourdomain.com/admin/login` 与接口路径验证响应。

## 客户端配置与联调
1) 设置 `BASE_URL`
- 在客户端将 `APIClient.baseURL` 指向线上地址（如 `https://api.yourdomain.com`）。
- 推荐改为从 `Info.plist` 或配置文件读取（便于构建环境切换）。
2) 主页与阅读
- 主页：启动时调用 `/v1/editor-picks` 与 `/v1/books?page=1&page_size=24`，滚动加载分页。
- 阅读：最后一页调用 `/v1/books/{id}/recommendations?age=&limit=5`。
3) 验证用例
- 后台创建一本新书并发布；客户端主页应显示于推荐流或编辑推荐（按开关与排序）。
- 上传图片后返回 `file_url`，在页面管理中展示；客户端阅读页展示页面图。

## 后台操作平台联调
- 登录：`/admin/login`（示例账户当前固定），进入 `admin/books`。
- 新建：`/admin/books/new` 填写表单并提交，编辑推荐上限提示生效。
- 页面管理：`/admin/books/{id}/pages`，批量上传图片（开发环境走 `/v1/admin/upload`），获得 `file_url`。

## 安全与生产化待办
- CORS：限制到你的客户端域名或调试域；不要长期使用 `*`。
- 会话：将 `admin_session` 设置为 `Secure` + `HttpOnly` + `SameSite=Lax`；引入 CSRF token。
- 认证：替换演示登录为数据库账户与 bcrypt/argon2id 密码哈希。
- 对象存储：将上传改为预签名 URL 直传（S3/R2），减少容器磁盘使用与带宽占用。
- 日志与监控：接入结构化日志（zerolog）、/metrics（Prometheus 可选），错误告警与速率限制。

## 验收清单
- Render 或自建环境的 HTTPS 域名可访问 `/healthz`。
- 客户端主页与阅读页完全走线上接口，分页与相关推荐正确。
- 后台能登录、创建书籍与上传图片，客户端可见。
- 基础安全配置与限流到位，无明显漏洞。
