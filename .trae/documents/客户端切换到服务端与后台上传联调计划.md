## 目标
- 让现有客户端改为调用服务端接口（主页与阅读模块），保留离线 fallback。
- 完成后台管理的表单页面（登录、书籍与页面管理），实现图片上传与联调。

## 客户端改造
- 配置与网络层
  - 新增 `BASE_URL` 配置（如 `https://picturebook-server.onrender.com`），支持环境切换与超时/重试。
  - 添加 `APIClient`（`URLSession` + async/await）：封装 `GET /v1/editor-picks`、`GET /v1/books`、`GET /v1/books/{id}`、`GET /v1/books/{id}/recommendations`。
- `ContentService` 改造
  - 增加 `loadRemote()`：拉取编辑推荐与推荐流分页；失败时自动 fallback 本地 JSON。
  - 统一数据模型（服务端 JSON 字段与本地一致），缓存首屏数据；分页根据服务端 `paging.has_more` 决定是否继续拉取。
- 页面改造
  - 主页：首次进入调用 `editor-picks` 与 `books?page=1&page_size=24`；滚动触发 `page++` 拉取下一页。
  - 阅读页：读完调用 `GET /v1/books/{id}/recommendations?age=&limit=5` 获取相关推荐并展示。
- 错误与占位
  - 弱网与失败显示占位卡片与重试；进度条与交互保持不变。

## 后台管理（表单与流程）
- 登录与安全
  - 登录页：邮箱/密码（bcrypt），会话 Cookie，CSRF token；基础速率限制。
- 书籍管理
  - 列表页：搜索/筛选（状态、编辑推荐），分页。
  - 新建/编辑页：标题、适龄、标签、主题、热门度、编辑推荐开关；提交校验（编辑推荐≤5）。
  - 删除操作：软删或直接删（MVP 直接删）。
- 页面管理与上传
  - 页面列表与排序（index 字段）；支持批量上传图片生成页面记录。
  - 上传实现（MVP）
    - 开发环境：`POST /v1/admin/upload` 接收 `multipart/form-data`，保存到 `uploads/` 并返回 `file_url`；`GET /assets/*` 静态暴露。
    - 生产环境：提供 `POST /v1/admin/upload-url` 生成 S3/R2 预签名 URL，前端直传，随后提交页面记录（推荐）。
- 表单技术
  - 使用 `html/template` + 少量 HTMX/Alpine.js 增强，快速实现无 SPA 的后台页面。

## 服务端接口补充
- 公共接口：已实现 `editor-picks`、`books`、`book`、`recommendations`。
- 后台接口：
  - `GET/POST/PUT/DELETE /v1/admin/books`（现有已支持 `POST`；补齐其余）
  - `GET/POST /v1/admin/books/{id}/pages`（创建/批量创建）
  - `POST /v1/admin/upload`（开发环境）或 `POST /v1/admin/upload-url`（生产环境预签名）
  - `GET /assets/*`（开发环境静态资源）

## 部署与配置
- Docker 镜像：保留 `uploads/` 目录为持久卷（开发/测试），Render/其他平台使用对象存储（生产）。
- 环境变量：`CORS_ALLOWED_ORIGINS`, `JWT_SECRET`, `DATABASE_URL`（接入 DB 时），`S3_*`（生产上传）。
- Render 部署：使用现有 `server/Dockerfile` 与 `deploy/render.yaml`，绑定自定义域名；健康检查 `/healthz`。

## 联调步骤
1) 在本地或云端启动服务端，确认可访问 `GET /healthz`。
2) 客户端设置 `BASE_URL` 并切换 `ContentService` 到远端拉取；运行主页与阅读页验证分页与推荐。
3) 打开后台登录，创建书籍与页面（上传图片），发布后在客户端拉取验证展示。
4) 验证编辑推荐上限提示与接口校验；弱网与失败时客户端 fallback。

## 验收标准
- 主页编辑推荐与推荐流分页全部来自服务端，滚动加载正常。
- 阅读页最后一页弹窗展示服务端相关推荐，点击跳转正常。
- 后台能创建/编辑/删除书籍与页面并上传图片，发布后客户端可见。
- 容器化启动成功，Render 可用，健康检查与 CORS 正常。
